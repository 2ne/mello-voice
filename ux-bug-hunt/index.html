Bridge

Today is the compass.

We're not doing art critique — we're debugging user flows.

  • 1 Can someone complete the happy path without guessing?
  • 2 Does every state exist — loading, empty, error, success?
  • 3 If they fail, can they recover without losing work?
Speaker notePin these three questions in your team's PR template. This is the takeaway artifact.
Round 1 · Visual hierarchy
Which action should win?

When two buttons look equally important, users hesitate — and often pick wrong.

→ Switch to Spot the UI · Round 1 and vote A or B.

DebriefLaw: Von Restorff effect + visual hierarchy. Dev hook: "Which CTA gets the keyboard focus path?"
Round 2 · Error recovery
Errors should help, not blame.

"Invalid input" tells the user they failed. A good message tells them how to succeed.

→ Spot the UI · Round 2

DebriefHeuristic: Help users recognize, diagnose, and recover from errors. Dev hook: "What's the edge case when the API 500s?"
Round 3 · System status
Silence feels like a bug.

If nothing happens after a click, users click again — or leave.

→ Spot the UI · Round 3

DebriefHeuristic: Visibility of system status. Dev hook: "Where's the loading state in your state machine?"
Round 4 · Cognitive load
Don't make me think on page one.

Progressive disclosure beats a wall of fields — especially in high-stakes flows.

→ Spot the UI · Round 4 then UX Quest

DebriefLaws: Hick's Law + Miller's Law. Ask: "Which round would have caught a bug you shipped last month?"
